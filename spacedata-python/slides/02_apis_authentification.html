Client-serveur & HTTP

Le modèle requête / réponse

HTTP (HyperText Transfer Protocol) est le protocole de communication standard du web : il définit comment un client formule une requête et comment un serveur y répond, quels que soient leurs langages respectifs.

💻
Client
  • Navigateur web
  • Script Python (requests)
  • Application mobile
  • Terminal (curl)
requête →
← réponse
🖥️
Serveur
  • API REST (FastAPI, Django)
  • Serveur web (Nginx, Apache)
  • Service cloud (AWS, Google Maps)
  • Base de données exposée en API

HTTPS = HTTP + chiffrement (TLS) : les échanges deviennent illisibles pour un tiers qui les intercepterait. En production on utilise presque toujours HTTPS ; notre micro-API tourne en simple HTTP car elle reste en local (127.0.0.1), jamais exposée sur le réseau.

Client-serveur & HTTP

Anatomie d'une URL

Avant de regarder une requête HTTP en détail, décomposons l'adresse qu'on appelle : une URL (Uniform Resource Locator) a toujours la même structure.

URL complète
http://127.0.0.1:8000/villes
^^^^   ^^^^^^^^^ ^^^^ ^^^^^^
schéma    host   port  path
  • Schéma (http:// ou https://) — le protocole utilisé pour la communication
  • Host (127.0.0.1) — l'adresse de la machine qui héberge le serveur
  • Port (8000) — la "porte" sur laquelle le serveur écoute ; une même machine peut faire tourner plusieurs serveurs sur des ports différents
  • Path (/villes) — la route demandée sur ce serveur, celle que votre code FastAPI associe à une fonction

127.0.0.1 est une adresse spéciale appelée localhost : elle désigne toujours "cette machine elle-même", quel que soit l'ordinateur sur lequel on l'exécute. C'est pour ça que votre micro-API, lancée en local, est jointe sur 127.0.0.1 et jamais accessible depuis un autre ordinateur (sauf solution comme ngrok, vue plus tard).

Le DNS : traduire un nom en adresse IP

En dehors du réseau local, le host d'une URL est en général un nom de domaine (earthquake.usgs.gov) plutôt qu'une adresse IP brute. Mais un ordinateur ne communique qu'avec des adresses IP : il faut donc une étape de traduction.

💻
Votre client
  • Demande : "quelle est l'IP de
    earthquake.usgs.gov ?"
requête DNS (UDP/53) →
← adresse IP
📇
Serveur DNS
  • Un annuaire géant qui associe chaque nom de domaine à une adresse IP

Le DNS (Domain Name System) fonctionne comme un répertoire téléphonique. C'est un protocole distinct d'HTTP : requests.get("https://...") déclenche cette résolution DNS automatiquement en arrière-plan, avant même d'initier la connexion HTTP.

⚠️ Configuration : Pour changer de résolveur DNS, vous devez obligatoirement renseigner son adresse IP brute (l'ordinateur ne peut pas deviner le nom de domaine du serveur DNS avant de l'avoir interrogé !).
Quelques serveurs DNS publics célèbres :
  • Google DNS : 8.8.8.8 & 8.8.4.4
  • Cloudflare : 1.1.1.1 & 1.0.0.1 (Axé sur la vie privée et la rapidité)
  • Quad9 : 9.9.9.9 (Bloque les domaines malveillants par défaut)

Client-serveur & HTTP

Un paramètre essentiel : timeout

Par défaut, requests attend une réponse indéfiniment. Si le serveur ne répond jamais, votre script ou votre notebook reste figé — sans message d'erreur.

demo.py
try:
    reponse = requests.get(
        URL, params=params, timeout=10,
    )
    reponse.raise_for_status()
except requests.exceptions.Timeout:
    print("Le serveur met trop de temps à répondre")
except requests.exceptions.RequestException as erreur:
    print(f"Erreur réseau : {erreur}")
  • timeout=10 — abandonne après 10 secondes sans réponse et lève une exception Timeout
  • On peut aussi passer un tuple timeout=(3, 10) : 3 s pour établir la connexion, 10 s pour recevoir la réponse
  • C'est exactement ce motif (timeout + try/except) que vous retrouverez dans les TP séances 2 et 4

Anatomie d'une API REST

Documenter une API : Swagger / OpenAPI

OpenAPI est un standard décrivant une API de façon lisible par une machine ; Swagger UI en affiche une documentation interactive testable dans le navigateur. FastAPI la génère automatiquement — mais sa qualité dépend de ce que vous écrivez.

  • La docstring de la fonction devient la description de l'endpoint
  • Les type hints et modèles Pydantic génèrent le schéma des paramètres et du corps
  • summary=, tags= sur le décorateur classent et titrent chaque endpoint
  • response_model= documente la forme exacte du JSON renvoyé
server.py
class Ville(BaseModel):
    """Une ville et sa population."""
    nom: str
    region: str
    population: int

@app.get("/villes/{id}", response_model=Ville,
         tags=["villes"])
def obtenir_ville(id: int):
    """Retourne une ville à partir de son id."""
    ...

Générer et consulter sa documentation

Vous n'avez rien à générer manuellement : FastAPI construit le schéma OpenAPI au démarrage, à partir des docstrings et des types que vous avez écrits. Il ne reste qu'à aller le consulter.

  • 1Lancer le serveur — fastapi dev server.py

  • 3Déplier un endpoint — paramètres, corps attendu, réponses possibles, tout généré depuis votre code
  • 4"Try it out" → "Execute" — remplir les champs et exécuter une vraie requête sans quitter le navigateur
  • 5Alternative : /redoc — présentation en lecture seule, plus soignée pour partager la doc à un tiers

Construire sa propre API

Une mini-app FastAPI, en quelques lignes

server.py
from fastapi import FastAPI

app = FastAPI()

villes = [{"nom": "Paris", "population": 2145000}]

@app.get("/villes")
def lister_villes():
    return villes

@app.post("/villes")
def ajouter_ville(ville: dict):
    villes.append(ville)
    return ville
  • FastAPI() crée l'application ; chaque fonction devient une route grâce à un décorateur : @app.get(...), @app.post(...)
  • La valeur retournée par la fonction est automatiquement sérialisée en JSON
  • On lance le serveur avec fastapi dev server.py (rechargement automatique inclus)

Construire sa propre API

Un décorateur, c'est une fonction qui en enveloppe une autre

Exemple hyper basique
demo.py
def chronometre(fonction):
    def wrapper(*args, **kwargs):
        debut = time.time()
        resultat = fonction(*args, **kwargs)
        duree = time.time() - debut
        print(f"{fonction.__name__} : {duree:.3f}s")
        return resultat
    return wrapper

@chronometre
def calcul_long():
    time.sleep(1)
Vérifier une clé API, en pratique
server.py
def verifier_cle(authorization: str = Header(default=None)):
    """Dépendance : vérifie que le header Authorization
    contient la bonne clé API."""
    if authorization != API_KEY:
        raise HTTPException(
            status_code=401,
            detail="Clé API manquante ou incorrecte",
        )

@app.post(
    "/villes", status_code=201, tags=["villes"],
    dependencies=[Depends(verifier_cle)],
)
def ajouter_ville(ville: dict):
    ...

On n'écrit pas son propre décorateur pour vérifier une clé API : FastAPI fournit exactement ce mécanisme via Depends(), passé dans dependencies=[...] du décorateur de route. Mais @app.get(...) et @app.post(...) restent eux-mêmes des décorateurs : ils enregistrent votre fonction comme gestionnaire d'une route, sans changer son code — comprendre les décorateurs reste donc indispensable.
